# LOADDER MASTER ARCHITECTURE v1

## Vision

Loadder is not a collection of AI tools.
Loadder is a Business Improvement Operating System.

Core loop:

UNDERSTAND → OBSERVE → DIAGNOSE → DECIDE → ACT → MEASURE → LEARN → repeat

## Core Principles

### Evidence before Intelligence

No AI-generated assumption becomes truth without evidence.

Truth states:

- UNKNOWN
- OBSERVED
- INFERRED
- VALIDATED

### Complexity in Backend, Simplicity in UX

Users describe goals. Loadder handles operational complexity.

### Reuse before rebuild

Existing foundations remain authoritative:

- Business Context
- Business DNA
- Brand Book
- Website Builder
- Content Studio

## Core Domains

### Business Understanding

Source of truth for business profile, DNA, goals, audience and brand context.

### Website Domain

Website Builder remains the execution engine. AI recommends; Builder executes.

### Customer Domain

Visitor → Lead → Customer → Repeat Customer → Advocate

### Intelligence Domain

Contains:

- Diagnosis Engine
- Decision Engine
- Experiment Engine
- Learning Engine

## Recommendation Contract

Every recommendation must contain:

- problem
- evidence
- confidence
- expected impact
- required action
- measurement plan

## Learning Memory

Every action becomes knowledge:

Situation → Decision → Execution → Outcome → Knowledge

## Event Architecture

Important business actions become events:

- business.created
- website.published
- lead.created
- campaign.started
- order.completed
- experiment.finished

## Development Rule

Before adding any feature ask:

Does this improve:

- Understand?
- Observe?
- Diagnose?
- Decide?
- Act?
- Measure?
- Learn?

If not, do not build it.
